# 음성 전처리·VST 확장 제안

검토일: 2026-09-24. 아래는 초기 설계 제안이다. 이후 사용자 요청으로 최소 VST3 체인을 먼저 구현했다. **현재 구현 범위와 검증은 [VST-CHAIN.md](VST-CHAIN.md)를 기준으로 한다.** RNNoise/DeepFilterNet 내장 처리는 여전히 제안 단계다.

권장 순서는 **텍스트 기반 컷편집 안정화 → 선택형 내장 잡음 억제 → 사용자 VST3 연결**이다. 스트리머 영상에서는 목소리뿐 아니라 웃음, 반응, 게임 소리도 편집 재료다. 전처리는 기본적으로 끄고, 켤 때도 약한 설정부터 비교한다. 원본과 시간축은 항상 보존한다.

## 편집 기능의 방향

Cutback은 자막의 단어 단위 편집, 텍스트 기반 컷, 무음·간투사·반복 구간 처리, 번역, 멀티캠 전환을 제품 기능으로 제시한다. 이 중 VOICESUBSEP의 우선 대상은 **발화 선택으로 컷 지정, 삭제 후보 검토, 자막·메모 동기화**다. 멀티캠·모션 자막 전체를 첫 범위로 가져오지는 않는다. 소개 페이지의 생산성·정확도 수치는 이 앱의 성능 근거로 사용하지 않는다. [Cutback 공식 기능 소개](https://cutback.video/ko/premiere-assistant)

무음 삭제는 음량 임계값만으로 확정하지 않고 VAD와 자막을 함께 써서 **후보만 제안**한다. 말머리·말끝에 여유를 두고, 웃음·놀람·짧은 맞장구와 말 없는 게임 장면은 사용자가 남길 수 있어야 한다. 자동 화자 구분이 실패한 짧은 발화를 무음으로 간주해서는 안 된다. 자막의 단어 시간이 오래됐거나 단어 중간을 자르는 경우에는 기존 컷 경계 검수를 유지한다.

가능한 녹음부터 마이크·음성 채팅·게임 오디오를 OBS 등의 별도 트랙으로 받는 것을 우선한다. 이미 섞인 음원에서 잡음을 억제하는 방법보다 **어느 소리를 분석하고 어느 소리를 보존할지 직접 선택하는 구조**가 목적에 맞는다. 트랙 선택과 여러 트랙의 동시 혼합은 별도 기능으로 구분한다.

## 후보 비교

| 후보 | 적합한 용도 | 도입 판단 |
| --- | --- | --- |
| RNNoise 코어 직접 연결 | 내장 음성 잡음 억제의 첫 후보 | 작은 별도 처리기로 평가. BSD-3-Clause 고지와 배포 조건을 반영하기 쉬운 구성이므로 우선 검토 |
| werman Noise Suppression for Voice | 사용자가 가진 RNNoise 플러그인의 선택 연결 | 내장 기본 구성보다 VST3 호스팅 단계에서 평가. GPLv3 래퍼와 JUCE 사용 조건을 함께 검토 |
| DeepFilterNet | RNNoise와 비교할 음성 개선 대안 | 48 kHz 전대역 음성 처리, 지연 보정 경로를 평가. 현재 자료만으로 더 좋은 화자 구분·한국어 인식을 보장하지 않음 |
| Pedalboard | Python 기반 VST3 호스트 실험 | Windows 지원을 활용한 시제품 후보. GPLv3와 포함 라이브러리 조건을 확인한 뒤 배포 방식을 결정 |

RNNoise의 공식 예제는 48 kHz 모노 16비트 RAW PCM 입출력을 사용한다. 라이브러리 자체와 예제 파일 형식을 구분하고, 앱에서 디코딩·채널 처리·리샘플링을 맡는다. `autogen.sh`는 모델 파일을 자동 다운로드하므로 방송 중에는 그대로 실행하지 않는다. [RNNoise README](https://github.com/xiph/rnnoise) · [RNNoise COPYING](https://github.com/xiph/rnnoise/blob/main/COPYING)

werman 플러그인은 48 kHz 입력을 요구한다. 문서상 말하는 동안 큰 키보드 소리는 완전히 사라지기보다 줄어들 수 있고, 좋지 않은 마이크에서는 음성을 잡음으로 오인할 수 있다. VAD grace는 말끝 보호, retroactive grace는 말머리 보호에 쓰지만 후자는 지연을 만든다. 따라서 공격적인 게이트를 기본으로 켜지 않는다. **다중 화자의 겹친 말을 분리하거나 게임 음악을 정확히 제거하는 기능으로 제시하지 않는다.** 래퍼는 GPLv3이며 JUCE를 GPLv3로 사용한다. [werman 공식 README](https://github.com/werman/noise-suppression-for-voice)

DeepFilterNet은 48 kHz 음성 개선을 대상으로 하며 CLI에 STFT·lookahead 지연 보정 옵션을 제공한다. 저장소 코드는 MIT 또는 Apache-2.0 선택 라이선스다. 실제 배포할 모델·바이너리·의존성은 선택 버전을 고정해 함께 확인한다. [DeepFilterNet README](https://github.com/Rikorose/DeepFilterNet) · [라이선스](https://github.com/Rikorose/DeepFilterNet/blob/main/LICENSE)

Pedalboard는 Python에서 외부 VST3 효과를 로드할 수 있고 Windows를 지원한다. 라이선스는 GPLv3다. 별도 프로세스로 실행한다는 사실만으로 배포 라이선스 문제가 자동 해결된다고 보지는 않는다. [공식 문서](https://spotify.github.io/pedalboard/) · [공식 라이선스](https://spotify.github.io/pedalboard/license.html)

## 원본 시간축을 지키는 처리 구조

설정은 **분석용**, **들어보기용**, **내보내기용**으로 각각 선택한다. 분석에 잡음 억제를 켰다는 이유로 게임 오디오까지 바뀐 미디어를 내보내지 않는다. Whisper에는 원본·약한 잡음 억제본을 비교하고, Nemotron에도 두 입력을 비교한다. 잡음 억제가 화자 특징까지 바꿀 수 있다는 가능성을 검증해야 하므로, 듣기 좋아졌다는 이유만으로 화자 구분 품질이 나아졌다고 판단하지 않는다.

추후 처리 인터페이스는 아래 항목을 계약으로 삼는다. **아직 프로젝트 스키마나 실행 코드에 추가하지 않는다.**

- 입력: 원본 식별자·해시, 오디오 트랙, 목적, 처리 엔진·버전, 파라미터 또는 사용자 플러그인 상태.
- 출력: 로컬 파생 음원, 샘플레이트·채널 구성, 총 샘플 수, 측정한 처리 지연과 보정량, 설정 해시, 경고.
- 보존 규칙: 원본을 덮어쓰지 않고, 동일 샘플레이트에서 전후 총 샘플 수와 길이를 일치시킨다. 플러그인 지연과 끝부분 잔여 출력을 처리한 뒤 시작점·길이를 보정한다. 전처리 단계에서는 침묵이나 발화를 삭제하지 않는다.
- 캐시: 원본 해시 + 트랙 + 엔진 버전 + 설정·플러그인 상태로 구분한다. 설정이 바뀌면 이전 분석 결과를 새 음원 결과로 취급하지 않는다.

VST 확장은 **Windows x64 VST3만 먼저**, 사용자가 설치한 플러그인을 명시적으로 선택하는 방식으로 제한한다. 초기에는 검증한 플러그인 목록을 사용하고 VST2·플러그인 묶음 배포는 제외한다. 스캔과 실제 처리를 UI·분석 서버와 분리된 작업 프로세스에서 실행하며, 충돌·응답 없음·취소 시 편집 프로젝트는 유지한다. 지연 보정, 플러그인 상태 저장, 캐시 무효화, 설정 복원 실패 표시까지 호스트 기능에 포함한다. 프로세스 분리는 충돌 격리 수단이며 플러그인의 보안 격리를 보장하지 않는다.

## 다음 단계의 통과 기준

먼저 같은 **30초 구간**을 원본/약한 처리로 번갈아 듣게 한다. 마이크 잡음·키보드·게임 음악·짧은 첫 단어·웃음·동시 발화를 포함한 여러 구간을 사용한다. 잡음 감소뿐 아니라 잘린 음절, 목소리 변형, 미배정 화자와 잘못 배정된 화자, 한국어 자막 오류를 함께 기록한다.

구현 검증에서는 원본 파일 해시 보존, 전후 샘플 수·길이 일치, 시작·끝 및 컷 경계의 싱크, 취소·충돌 복구, 재실행 시 동일 설정 복원을 확인한다. 실제 녹음에서 비교하기 전에는 RNNoise·DeepFilterNet의 우열이나 화자 구분 개선을 결론 내리지 않는다. 모델을 준비할 시점에는 다운로드 크기를 먼저 확인하고 당시 대역폭 제한을 적용한다.
