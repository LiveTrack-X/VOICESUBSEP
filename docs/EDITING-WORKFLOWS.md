# 편집·복구·녹음의 현재 사용 흐름

기준: **0.3.0 대상 편집 흐름**. 처음 사용한다면 [사용자 가이드](USER-GUIDE.md)를 먼저 확인하세요. 실제 설치·게시·검증 상태는 [0.3.0 릴리즈 기록](releases/v0.3.0.md)을 따릅니다. 라이브·믹서·명세 서명 인앱 업데이트의 범위는 [기능 현황](FEATURE-STATUS.md), 업데이트 절차는 [설치형 안내](DESKTOP.md#사용자가-선택하는-업데이트)를 우선합니다. 아래 이전 검사 수치는 당시 기록으로 구분합니다.

[확장 제안](EXPANSION-ROADMAP.md)과 [라이브 캡처 제안](LIVE-CAPTURE-PLAN.md)은 이전 설계 기록입니다. 컷의 원본/출력 시간 매핑과 화면·음성 언어는 [컷편집·다국어 계약](CUTS-AND-LANGUAGES.md), VST는 [VST 체인 사용법](VST-CHAIN.md), 설정과 로그는 [설정과 오류 로그](SETTINGS-AND-LOGS.md)를 참고하세요. 자막 번역·AI 자동 요약은 제거했습니다.

## 이번 점검에서 수정한 여섯 가지 문제

| 재현 조건과 기존 문제 | 현재 처리 |
| --- | --- |
| 긴 자막을 합쳐 한 자막이 10,000자를 넘으면 저장 계약을 위반하고, 자동 저장·파일 저장·재열기 과정에서 내용이 유실될 수 있었습니다. | 합치기와 일괄 치환 결과를 변경 전에 검증합니다. 자동 저장도 유효한 프로젝트인지 검사하여 잘못된 데이터로 현재본·이전 정상본을 덮어쓰지 않습니다. |
| 렌더 또는 VST 미리듣기 중 서버 연결이 끊기거나 작업이 404로 사라지면 창 닫기가 잠길 수 있었습니다. | 연결 상태를 작업 실패와 구분하고 재연결·화면에서 나가기를 제공합니다. 404는 존재하지 않는 작업으로 종료 처리합니다. 연결이 끊겼다는 이유만으로 서버의 처리가 취소됐다고 표시하지 않습니다. |
| 같은 파일로 분석·렌더를 반복하면 업로드 사본이 중복 생성되어 저장 공간이 늘었습니다. | 프런트엔드에서 같은 File의 진행 중 업로드와 결과를 공유하고, 서버는 파일 내용의 SHA-256으로 사본을 재사용합니다. 서버 재시작 뒤에도 해시 인덱스를 재사용합니다. |
| 자막이 0개이면 첫 자막을 추가하는 버튼이 없었습니다. | 빈 프로젝트에도 `+ 자막`을 표시합니다. 연결된 미디어의 끝을 넘는 자막은 만들지 않습니다. |
| 공백 없는 긴 URL·문자열이 자막 입력칸과 목록의 폭을 밀어냈습니다. | 입력칸과 그리드의 최소 너비를 제한하고 셀 안에서 줄이 바뀌도록 처리합니다. |
| 설치형 앱의 백엔드 실행 파일이 없으면 로그 초기화 전에 실패하여 시작 오류가 기록되지 않았습니다. | 백엔드 시작 검사보다 먼저 앱 로그를 준비합니다. 로그 저장 자체가 불가능한 환경까지 기록 성공을 보장하지는 않습니다. |

이 수정의 자동 검증은 데이터·오류 처리 계약을 확인합니다. 실제 한국어 인식률, 회의록 내용의 타당성, 모든 VST의 처리 품질 또는 기존 설치본 동작을 대신 입증하지 않습니다.

## 많은 자막을 검수하기

자막 목록은 **한 페이지에 100행**을 표시합니다. 검색·인물·검수 필터로 범위를 좁히고 `여러 자막 편집 · 찾기/바꾸기`에서 필요한 행을 선택합니다.

- `이 페이지 선택`은 현재 페이지, `필터 결과 모두 선택`은 현재 필터에 해당하는 전체 자막을 선택합니다. 선택 개수를 확인한 뒤 작업하세요.
- 선택한 자막의 인물을 한 번에 바꾸거나 검수 완료·취소·삭제를 적용할 수 있습니다.
- 찾기/바꾸기는 **대소문자를 구분하는 일반 문자열 치환**입니다. 선택한 자막 또는 현재 필터 결과를 대상으로 하며 정규식은 아닙니다. 하나라도 글자 수 제한을 넘으면 전체 변경을 거부합니다.
- `다음 검수 필요`, `다음 미배정`으로 현재 필터 안의 다음 대상에 이동합니다.
- 타임라인에서 자막을 열면 해당 행이 있는 페이지로 이동합니다. 해당 행을 가리는 필터가 있으면 해제해 보여줍니다.

추가·나누기는 프로젝트의 20,000개 자막 한도를, 합치기·치환은 자막당 10,000자 한도를 지킵니다. 텍스트나 경계를 바꿔 기존 단어별 시간이 맞지 않게 되면 그 단어 타이밍을 제거합니다. 이전 프로젝트의 번역 필드는 파일 호환을 위해 보존하지만 번역 화면·출력은 제공하지 않습니다.

타임라인 접기·높이 조절, 목록의 촘촘한 표시, 자막 집중 보기도 사용할 수 있습니다. 화면 배치는 기기에 저장되며 프로젝트 JSON의 편집 내용과는 별도입니다.

## 자동 저장과 복구

일반 편집은 브라우저에 자동 저장하고, 최근의 유효한 프로젝트 한 개를 이전본으로 보관합니다. 이전본은 같은 프로젝트에서 최대 1분 간격 또는 프로젝트 전환 때 교체하므로 모든 편집 단계의 이력은 아닙니다.

`자동 저장 복구`에서 현재본·이전 정상본·보관된 오류 원본을 확인하고 JSON으로 내려받을 수 있습니다. 유효한 항목을 복구하면 프로젝트를 전환하며 이전 프로젝트의 실행 취소 이력이 섞이지 않습니다. 읽을 수 없는 현재본은 먼저 원문 그대로 보관해야 교체할 수 있습니다. 오류 원본 정리는 다운로드 후 별도로 확인합니다.

브라우저 저장 공간 부족으로 이전본 보관이 실패했지만 현재본 저장은 성공한 경우에도 경고합니다. 자동 저장은 브라우저 데이터 삭제·기기 고장을 막지 못하므로 중요한 작업은 **프로젝트 JSON으로 따로 저장**하세요. JSON에는 자막·인물·노트·컷·문서 정보가 들어가지만 원본 미디어는 포함되지 않습니다.

## 파형과 자막 경계

원본을 연결한 뒤 타임라인에서 `파형 불러오기`를 누릅니다. 오디오 트랙이 여러 개면 `파형 오디오 트랙`에서 고르고 다시 불러옵니다. 서버는 FFmpeg로 제한된 수의 피크를 만들며 브라우저가 긴 녹음 전체를 PCM으로 풀어 메모리에 올리지 않습니다. 파형은 탐색용 요약이며 샘플 단위 편집용 계측값은 아닙니다.

파형이나 자막을 클릭하면 원본 시간으로 이동합니다. 선택한 자막의 시작·끝 손잡이를 드래그하면 경계를 조절하며, 놓을 때 한 번의 편집으로 확정됩니다. 손잡이에 초점을 둔 상태에서 좌우 화살표는 10ms, Shift와 함께 누르면 100ms씩 조절합니다. 취소된 드래그는 확정하지 않습니다. 경계는 원본 범위와 최소 길이 10ms를 지킵니다.

## 자막 전달: ASS와 인물별 ZIP

`스타일 포함 ASS`는 인물·자막에 설정한 글꼴, 크기, 색, 굵기, 외곽선, 배경, 위치 정보를 자막 파일에 담습니다. 1920×1080 기준이며 표시 결과는 플레이어의 글꼴과 줄바꿈에 따라 달라질 수 있습니다. 편집기 미리보기와 픽셀 단위로 같다는 보장은 없습니다. 이 기능은 렌더 영상에 자막을 직접 입히는 기능이 아닙니다.

`인물별 SRT 묶음 ZIP`에는 다음 파일이 들어갑니다.

- 전체 자막 SRT와 내용이 있는 인물별 SRT, 필요한 경우 미배정 SRT
- 편집 메모 CSV
- 인물 ID·이름·색상·파일명·시간 기준을 기록한 manifest JSON

ZIP에는 원본 미디어·프로젝트 JSON·ASS가 들어가지 않습니다. SRT 자체는 글꼴·색상 스타일을 보존하지 않습니다. ASS와 ZIP은 편집한 원문의 **원본 시간 기준**입니다. 컷이 반영된 출력 시간 기준 SRT·메모 CSV는 렌더 결과 창에서 받습니다.

## OBS 등에서 분리해 녹음한 트랙 분석

이 기능은 이미 각 인물의 목소리가 따로 녹음된 파일에 사용합니다. 한 트랙에 여러 사람이 섞여 있으면 일반 Nemotron 분석을 사용하세요.

1. 원본 파일을 연결하고 필요한 인물 이름을 준비합니다.
2. 로컬 분석 창의 `분리된 화자 트랙`에서 `OBS 등에서 따로 녹음한 트랙을 인물별로 연결`을 켭니다.
3. 분석할 트랙과 각 트랙의 인물을 명시적으로 연결합니다. 최대 8개를 선택할 수 있습니다.
4. 전체 소리가 중복으로 들어 있는 믹스 트랙, 게임 소리만 있는 트랙 등은 제외합니다.
5. 분석 결과의 인물과 시간을 확인하고 적용합니다.

선택한 트랙은 로컬에서 순서대로 전사하고 원본 타임스탬프를 유지해 합칩니다. 이 경로는 지정한 트랙→인물 연결을 사용하므로 분리된 트랙 사이에 Nemotron 화자 구분을 다시 적용하지 않습니다. 동시에 말한 구간도 각 트랙의 자막으로 유지됩니다. 하나의 트랙에 섞인 목소리를 분리하거나, 서로 다른 녹음 파일의 시계 차이를 자동으로 맞추는 기능은 아닙니다. VST 전처리를 선택했다면 같은 체인을 각 트랙에 적용합니다.

## 편집본 렌더와 작업 재열기

MP4 렌더는 `원본`, `30`, `60` 프레임을 선택할 수 있습니다. `원본`은 탐지한 소스 프레임률로 **고정 프레임률 재인코딩**하며 가변 프레임률을 그대로 보존하지 않습니다. 기본 렌더의 오디오는 **한 트랙**이고, 여러 파일·OBS 트랙의 음량·음소거·미리듣기·최종 합산 출력은 별도 [오디오 믹서](AUDIO-MIXER.md)를 사용합니다.

`작업 이력·저장 공간`에서 분석·렌더 상태를 확인하고 작업을 다시 열 수 있습니다. 창을 닫아도 서버가 살아 있으면 처리는 계속됩니다. 서버를 재시작하면 진행 중이던 작업을 중단된 작업으로 기록하며 계산을 자동으로 이어서 실행하지 않습니다.

분석 결과는 현재 프로젝트 ID와 연결 파일의 내용 기반 미디어 ID가 일치하고 해당 파일이 확인된 경우에만 편집기에 적용할 수 있습니다. 다른 프로젝트의 결과 또는 연결 정보가 없는 이전 작업을 현재 자막에 자동 적용하지 않습니다. 결과 JSON 다운로드는 별도로 가능합니다.

렌더는 시작 시점의 프로젝트 스냅샷을 저장합니다. 이력에서 다시 열어 받는 SRT·메모는 지금 편집 중인 프로젝트가 아니라 **해당 렌더의 스냅샷**을 기준으로 만듭니다. 스냅샷이 없는 오래된 결과는 미디어만 받을 수 있습니다. 서버 연결이 끊기면 다시 연결하거나 화면에서 나갈 수 있으며, 화면에서 나가는 것과 서버 작업 취소는 다릅니다.

## 미디어 캐시 정리

같은 File을 분석·파형·렌더에서 공유하고, 서버는 파일 내용의 해시로 같은 원본 사본을 재사용합니다. 이름이 같아도 내용이 다르면 다른 미디어입니다. 브라우저를 새로 열어 File 객체가 달라지면 서버가 내용을 확인하기 위한 업로드는 다시 필요할 수 있습니다. 따라서 브라우저를 다시 연 뒤의 재업로드까지 항상 생략하는 기능은 아닙니다.

`작업 이력·저장 공간`에 저장된 미디어 크기·정리 가능 용량·여유 공간이 표시됩니다. 수동 정리는 앱이 복사한 미디어만 대상으로 하며 사용자가 연 원본 파일을 지우지 않습니다. 대기·실행 중 작업, 완료된 결과가 참조하는 미디어, VST 미리듣기 및 진행 중 파형 작업은 보호합니다. 결과를 더 이상 보관할 필요가 없다면 종료된 작업 이력을 먼저 명시적으로 삭제한 뒤 참조가 풀린 캐시를 정리할 수 있습니다.

분석·렌더 결과와 캐시는 프로젝트 JSON 저장만으로 자동 정리되지 않습니다. 모델 캐시와 브라우저의 녹음 보관함도 이 미디어 정리와 별도입니다. 업로드 한 파일의 기본 한도는 8GiB이며 추출 WAV와 출력 파일을 위한 추가 공간이 필요합니다.

## 인터뷰와 근거가 있는 회의록

`인터뷰·회의록`을 열면 같은 자막을 바탕으로 문서를 편집합니다. 문서 데이터는 타임라인 편집 노트와 별도로 프로젝트에 저장합니다.

인터뷰 화면에서는 인물의 역할을 질문자·답변자·참여자로 지정하고 자막별로 질문·답변·기타를 수정합니다. 시간 표시를 누르면 해당 원문 자막으로 이동합니다. 현재는 분류된 전사문이며 여러 질문과 답변을 자동으로 묶는 계층형 Q&A 편집기는 아닙니다.

회의록은 요약·논의·결정·할 일 항목을 수동으로 추가하고, 원문 자막을 근거로 연결할 수 있습니다. 담당자와 기한도 직접 수정합니다. 근거를 선택할 때 자막 ID뿐 아니라 텍스트·시간·인물의 스냅샷을 저장합니다. 이후 자막이 바뀌거나 삭제되면 `근거 재확인 필요`로 표시합니다. 현재 원문과 일치하는 근거와 내용이 있어야 확정할 수 있으며, 근거를 갱신하면 다시 초안으로 검수합니다.

Ollama·클라우드 텍스트 AI·자동 회의록 생성은 제거했습니다. 기존 문서 데이터는 보존하며 항목은 직접 작성·검수합니다. 발언록·인터뷰·수동 회의 메모의 DOCX/TXT/HTML/XLSX/PDF 등 출력은 [사용자 가이드](USER-GUIDE.md#7-인터뷰와-회의록)를 따릅니다. 외부 LLM을 쓰려면 원문 발언록을 직접 내보내 사용할 수 있습니다.

## 마이크·시스템 소리 녹음과 복구

상단 `실시간 자막·녹음`에서 `녹음 후 분석` 또는 `라이브 자막 + 녹음`을 고르고 마이크·시스템 소리·둘 다를 선택합니다. 마이크 장치를 지정할 수 있으며 시스템 소리는 실제 오디오 공유 대상을 선택합니다. 브라우저·OS·공유 대상에 따라 지원이 달라지고 오디오 트랙이 없으면 시작을 거부합니다. 화면 공유에 영상 트랙이 필요해도 저장하는 것은 오디오입니다.

데스크톱 소스에는 사용자가 시작했을 때 마이크 권한을 확인하고 Windows 시스템 loopback 캡처를 선택하는 경로도 있습니다. 시스템 소리에는 통화뿐 아니라 게임·알림 등이 포함될 수 있습니다. 특정 설치본의 포함·장치 검증 여부는 해당 버전 릴리즈 기록을 확인하세요.

녹음은 소스별 마이크·시스템 소리와 분석용 혼합본을 보관합니다. 두 소스를 혼합할 때 각각 절반의 이득을 적용하며 소리를 스피커로 재생하는 모니터링은 하지 않습니다. 장치가 실제로 전달한 소리를 녹음하는 기능으로, 이미 섞인 참가자의 목소리를 분리하지 않습니다.

MediaRecorder가 약 **1초 단위**로 전달한 조각을 IndexedDB에 순서대로 저장합니다. 녹음 목록에서 소스별 파일과 메타데이터 JSON을 내려받고 확인 후 삭제할 수 있습니다. 메타데이터에는 시작·종료, 포맷, 소스별 시작 오프셋과 중단 상태를 기록합니다. 비정상 종료 뒤에도 저장을 마친 조각을 복구 대상으로 남깁니다. 마지막 미저장 조각은 잃을 수 있고, 중단된 컨테이너가 모든 플레이어에서 정상 재생된다는 보장은 없습니다.

한 세션의 모든 소스 파일을 합친 제한은 2GiB이며 브라우저 저장 공간 부족이 먼저 발생할 수 있습니다. 내보낼 때 조각을 File로 모으므로 큰 녹음은 추가 메모리를 사용합니다. 수시간 연속 녹음·장치 분리·OS 절전 후 복구의 실기기 품질은 별도 검증 대상입니다.

녹음 전용은 종료 뒤 `새 프로젝트로 분석`을 사용합니다. 라이브 모드는 **미리 캐시한 로컬 Whisper+Nemotron**을 세션 내 유지하며 약 4초 구간의 자막과 OBS 표시를 갱신합니다. 라이브 준비 전 짧은 파일로 같은 Whisper 모델·로컬 Nemotron 분석을 한 번 완료하세요. 라이브 중에는 모델을 받지 않습니다. 최대 2시간이며 초기 적응·겹친 말의 화자는 초안입니다. 개별 WASAPI 출력·ASIO·자동 드리프트 보정·장치 자동 재연결은 별도 범위입니다. 자세한 순서는 [라이브 사용법](USER-GUIDE.md#8-라이브-자막마이크시스템-소리-녹음)을 따릅니다.

브라우저가 만든 WebM에 길이 헤더가 없으면 FFmpeg가 원본을 바꾸지 않고 실제 오디오 길이를 확인합니다. 이 보완 검사는 단일 스레드·180초 제한으로 실행하며, 분석 준비와 컷 출력 모두 같은 검사를 사용합니다. 매우 긴 파일이 제한 시간에 걸리면 준비 오류를 표시합니다.

## 확인 범위

이 문서는 현재 소스의 기능·저장·오류 처리 계약을 설명합니다. 단위 테스트와 합성 FFmpeg 파일 검증, 브라우저의 편집 조작, 실제 GPU 모델 추론, 실제 마이크·시스템 소리 녹음, 설치본 배포는 서로 다른 확인 범위입니다. 이전 GPU 실측은 [Nemotron 실행 기록](NEMOTRON-SMOKE.md)에 보존하며 이번 확장의 인식률·회의록 품질·장시간 실시간 성능으로 확대 해석하지 않습니다. 통합 검증 결과와 배포 여부는 해당 실행 기록 또는 릴리스 기록을 기준으로 확인하세요.

아래 수치는 0.3.0 설치·릴리즈 작업 전인 2026-09-25의 원문 기록입니다. 제거된 생성 API 검사도 당시 이력으로 남겼으며 현행 제공 기능을 뜻하지 않습니다. 최신 수치·설치·게시 여부는 [0.3.0 기록](releases/v0.3.0.md)을 확인하세요.

- 프런트엔드 374개, 데스크톱·실행 도구 44개, 백엔드 588개 통과. Windows 심볼릭 링크 권한에 의존하는 기존 검사 1개는 건너뛰었습니다. TypeScript와 프로덕션 웹 빌드도 통과했습니다.
