## Recognition change / 음성 인식 변경

Local Whisper **AUTO** now means the recording's main language. File analysis uses initial language detection and keeps that language instead of switching on every segment. Live mode retains the first detected language with committed speech and a detection probability of at least 0.5; empty or uncertain windows retry. The task is explicitly transcription. A selected input language remains unchanged.

로컬 Whisper **AUTO**를 녹음의 주 언어라는 의미에 맞춥니다. 파일 초반에 감지한 언어를 유지하고 구간마다 바꾸지 않습니다. 라이브는 실제 반영하는 발화가 있고 언어 감지 확률이 0.5 이상일 때 처음 감지한 언어를 유지하며, 빈 결과·불확실한 결과는 다음 구간에서 재시도합니다. 작업을 전사로 명시하고 직접 고른 입력 언어는 유지합니다.

There is **no forced Korean fallback or blanket removal of foreign-language text**. Select the input language directly when the main language is known. Initial detection can still be wrong, noise/silence can still cause hallucinations, and mixed-language speech needs review against the source. This change does not alter cloud-provider language policies or guarantee improved accuracy on every recording. Existing running jobs are not rewritten by a source change.

**한국어 강제 대체나 외국어 문장 일괄 삭제는 하지 않습니다.** 주 언어를 알면 직접 선택하세요. 최초 감지도 틀릴 수 있고 소음·무음 환각이 모두 사라지는 것은 아닙니다. 다국어 자료는 원음 검수가 필요합니다. 클라우드 언어 정책을 바꾸거나 모든 자료의 정확도 향상을 보장하지 않으며, 소스를 바꿨다고 이미 실행 중인 작업이 변경되지는 않습니다.

The preview label now separates job elapsed time from **Last result update time: HH:mm:ss**, a local wall-clock time. / 분석 미리보기는 작업 경과 시간과 **마지막 결과 갱신 시각: HH:mm:ss**라는 현지 시각을 구분합니다.

## Long jobs and cache cleanup / 긴 작업과 캐시 정리

- **Background analysis:** close the analysis dialog and continue editing; the footer shows the tracked job and reopens its state, drafts or result. Page reload restores the job reference and queries the server. Completion does not apply captions automatically: the user verifies the same project/source and explicitly applies the result. Repeated connection failures pause polling and offer retry. Exiting the app/backend can interrupt work; this is not automatic computation recovery.
- **백그라운드 분석:** 분석 창을 닫고 편집하면 하단에 추적 작업이 남고 상태·초안·결과를 다시 엽니다. 새로고침 뒤 저장한 참조로 서버에 조회합니다. 완료 결과는 자동 적용하지 않고 같은 프로젝트·원본 확인 후 직접 적용합니다. 반복 연결 오류에는 조회를 멈추고 재확인을 제공합니다. 앱·백엔드 종료는 작업을 중단할 수 있으며 계산 자동 복구 기능은 아닙니다.
- **Queue control:** waiting jobs show their position/count and the running job's name, stage and progress. **Run this job next** preserves the current job and other waiting order. **Stop current job, then prioritize this job** confirms that exact current job and refuses stale confirmation. Native inference cannot be force-killed instantly: the next job waits until the current call returns and cancellation is acknowledged. Already completed results can survive a late stop request; source files and previously applied captions remain.
- **대기열 조작:** 순서·대기 수와 현재 실행 작업의 이름·단계·진행률을 표시합니다. **이 작업을 다음으로**는 현재 작업과 나머지 순서를 보존합니다. **현재 작업 중단 후 우선 실행**은 확인한 바로 그 작업을 대상으로 하며 대상이 바뀌면 거부합니다. 네이티브 추론을 즉시 강제 종료하지 않고 호출 반환·취소 확인까지 다음 작업이 기다립니다. 늦은 중단 요청보다 먼저 완료된 결과는 남을 수 있으며 원본·기존 적용 자막은 유지합니다.
- **Manual cache cleanup:** confirm the displayed copies/count/size; at most 1,000 reviewed media IDs are included. Deletion rechecks job/preview/waveform reservations under the same lock. Later uploads are not included, retained job results still protect their inputs, and removed/skipped/failed counts are separate. User originals, models, recordings, project data and job-result folders are not cleanup targets. There is no automatic age/quota deletion.
- **수동 캐시 정리:** 표시한 사본 개수·크기를 확인하며 최대 1,000개 확인 목록만 정리합니다. 작업·미리듣기·파형 예약을 삭제와 같은 락에서 다시 검사합니다. 이후 업로드는 포함하지 않고 보관된 결과의 입력은 보호하며 삭제·건너뜀·실패를 구분합니다. 사용자 원본·모델·녹음·프로젝트·작업 결과 폴더는 정리 대상이 아니며 기간·용량에 따른 자동 삭제는 없습니다.
