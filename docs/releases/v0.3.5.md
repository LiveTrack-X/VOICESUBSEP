## Speaker assignment review / 미배정 보완 검토

The first stage of the [speaker-assignment strategy](../SPEAKER-ASSIGNMENT-STRATEGY.md)
preserves activity evidence and shows conservative boundary candidates for user
review. It never silently replaces existing assignments. Selected candidates are
applied as one undoable edit, with manual/reviewed captions and changed evidence
protected. Old results without stored activity remain explicitly unknown; new
analysis is not started automatically.

미배정 원인·검출 활동 근거와 보수적인 경계 후보를 표시하고, 사용자가 고른 후보만
실행 취소 가능한 편집으로 적용합니다. 수동 수정·검수 완료·이미 배정된 자막과 근거
생성 뒤 바뀐 자막은 보호합니다. 이전 결과의 없는 근거를 추측하지 않으며 새 분석을
자동 실행하지 않습니다. 후보는 정답이나 보정된 화자 신뢰도가 아닙니다.

No new embedding model, automatic bulk assignment or overlap-source separation is
introduced. Speaker identification quality requires labeled listening evaluation;
synthetic regression checks do not establish a reduction in real misassignments.

음성 임베딩 모델·자동 일괄 배정·겹침 음성 분리는 이번 첫 단계에 포함하지 않습니다.
실제 원음 검수 표본으로 오배정을 평가한 뒤 자동화 범위를 넓힙니다.

## Native VST windows / VST 전용 창

- Distinguish requesting, preparing, opening and visible-window status. / 요청·준비·창 열림 상태 구분.
- Raise the worker's own editor on initial open or explicit focus; never keep it permanently on top. / 최초 열기·명시적 앞으로 가져오기에서 해당 편집창만 전경으로 표시.
- Bound opening to 45 seconds and graceful close to 10 seconds; failed close does not apply partial state. / 열기 45초·저장 닫기 10초 제한, 실패 시 불완전한 설정을 적용하지 않음.
- Skip redundant explicit-name scanning and unused pre-open parameter readback; use normal priority for the interactive worker. / 선택한 플러그인 재검색·불필요한 열기 전 값 재수집 생략, 전용 창 작업은 일반 우선순위 사용.
- Import the web server only for a server launch, not a VST worker launch. / VST 작업 시작 때 웹 서버 초기화 제외.

The old label stayed busy for the editor's entire lifetime, including when its
window was already open behind the app. The user confirmed the window existed
behind the app/taskbar. Separately, a no-plugin startup probe measured the
installed 0.3.4 worker at 1.255 seconds; this is not Clear's initialization time.
The source entry module import changed from about 0.608 to 0.034 seconds after
removing its eager FastAPI import. The built 0.3.5 no-plugin worker probe took 0.580 seconds (one local run; not yet installed). In three alternating fresh-process pairs, Clear native initialization was 8.091 seconds with discovery and 8.093 seconds with direct loading (medians). Direct loading did not materially reduce native initialization. Actual GUI display latency remains unverified; the user's active analysis was not interrupted.

기존 ‘요청 중’ 문구는 별도 창이 이미 열린 뒤에도 계속 표시됐습니다. 사용자는 창이
뒤쪽·작업 표시줄에 있었음을 확인했습니다. 플러그인을 실행하지 않는 별도 측정에서
설치된 0.3.4 작업 시작은 1.255초였으며 Clear 자체의 초기화 시간은 아닙니다.
소스 진입 모듈은 FastAPI 선행 초기화를 제거해 약 0.608초에서 0.034초로 줄었습니다.
빌드한 0.3.5의 플러그인 없는 시작은 1회 측정에서 0.580초였습니다(아직 설치하지 않은 빌드). 새 프로세스 3쌍 비교에서 Clear 네이티브 초기화 중앙값은 기존 8.091초, 직접 로드 8.093초로 유의미한 차이가 없었습니다. 실제 GUI 표시 시간은 확인하지 않았으며 사용자 분석은 중단하지 않았습니다.

Upstream behavior reference: [Pedalboard 0.9.25 native editor and initialization](https://spotify.github.io/pedalboard/reference/pedalboard.html).

## Verification / 검증

Source verification: 892 frontend + 84 Node tests, 1,077 backend passed / 1 skipped, production web build, 43-module frozen-source match and offline bundled runtime/shutdown checks passed. Synthetic browser checks covered cause filtering, selected apply/undo, protected/stale captions, context playback while the dialog stays open, responsive footer access, VST stages/focus/close/cancel-detach and no console errors. These do not establish real-speaker accuracy or actual native GUI compatibility. Final package/publication/installation evidence is pending.

소스 검증: 프런트 892개 + Node 84개, backend 1,077개 통과 / 1개 생략, 웹 빌드·43개 모듈 동결 소스 일치·오프라인 번들 실행/종료 검사를 통과했습니다. 합성 자막 브라우저 검사에서 원인 필터·선택 적용/실행 취소·수정/검수 보호·구간 재생·작은 화면 하단 버튼·VST 상태/포커스/닫기/취소 후 연결 해제를 확인했습니다. 실제 화자 정확도와 네이티브 창 호환성을 뜻하지 않습니다. 패키지·게시·설치는 별도 기록 예정입니다.
