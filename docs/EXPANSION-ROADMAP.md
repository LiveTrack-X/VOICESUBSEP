# VOICESUBSEP 확장 제안: 컷 편집, 오디오 믹스, 인터뷰·회의록

작성: 2026-09-24. **초기 확장 제안 보관본입니다. 아래 단계·예상량·데이터 계약은 현재 기능 현황을 대신하지 않습니다.** 0.3.0 대상 구현은 [기능 현황](FEATURE-STATUS.md)·[사용자 가이드](USER-GUIDE.md), 게시·설치·검증 상태는 [릴리즈 기록](releases/v0.3.0.md)을 확인하세요.

**0.3.0 범위 안내:** 컷·렌더·5개 UI 언어, 자막 편집·복구, 인터뷰·수동 회의 메모, VST 전처리, [최대 16트랙 믹서·10초 미리듣기](AUDIO-MIXER.md), 캐시 전용 Whisper+Nemotron 라이브 자막·OBS 표시 경로가 구현 대상에 포함됩니다. 자막 번역과 AI 자동 회의 요약은 사용자 결정으로 제거했습니다. 이 문서의 초기 AI 초안 제안을 미완료 기능이나 향후 약속으로 읽지 마세요.

아래는 **2026-09-24의 역사적 제안**입니다. 이후 구현된 기능과 남은 제안이 섞여 있으며, 임의 WASAPI 출력·ASIO 라우팅·자동 드리프트 보정은 현재 범위 밖입니다. 믹서 원본은 SHA-256으로 재연결하지만 프로젝트의 모든 원본 연결이 같은 계약을 쓰는 것은 아닙니다. 구체적인 현행 동작은 위 최신 문서를 우선합니다.

제안 당시 v0.1의 자막·화자·시간 노트 편집, 프로젝트 저장, SRT 내보내기와 로컬 분석 구조를 출발점으로 삼았습니다. 아래 문서는 당시 계약이나 저장 형식을 직접 변경하지 않는 제안입니다.

## 권장 순서와 개발량

**먼저 원본을 보존하는 구간 삭제와 오디오 볼륨·음소거를 만들고, 그 시간 매핑을 인터뷰·회의록과 라이브 기록이 함께 사용하는 구조를 권장합니다.** 영상 편집 기능을 조금 추가하는 것은 가능하지만, 컷 이후에도 자막·메모가 맞게 따라가도록 만드는 부분이 핵심 개발량입니다.

아래 개발량은 현재 구조에서 추가할 작업의 상대적 규모입니다. 실제 편집·렌더 성능을 검증하기 전이므로 날짜 견적은 제시하지 않습니다. 테스트·오류 복구를 포함하며, Windows 우선, 소스 영상 1개, 재생 속도 1배, 이미 동기화된 오디오 트랙을 가정합니다. 모델 정확도 개선·설치 프로그램·서명·다른 편집기 전용 플러그인 작업은 별도입니다.

마이크·시스템 소리를 기록하는 라이브 기능은 [LIVE-CAPTURE-PLAN.md](LIVE-CAPTURE-PLAN.md)의 별도 제안입니다. 장치 접근·소스별 녹음·재연결·타임스탬프 안정성을 먼저 검증하고 이 문서의 저장 모델과 연결합니다. 라이브 캡처가 준비되기 전에도 v0.2와 v0.3은 파일 입력으로 개발·검증할 수 있습니다.

## v0.2: 간단한 편집의 범위

### 포함할 기능

- 구간의 시작·끝을 지정해 삭제하고, 삭제 표시를 해제해 복원합니다. 원본 파일은 덮어쓰지 않습니다.
- 원본 보기와 편집본 보기를 구분하고, 두 시간코드를 함께 표시합니다.
- 원본의 오디오 트랙을 개별적으로 선택·미리듣기하고 트랙별 볼륨과 음소거를 조정합니다.
- 소스 영상 1개와 이미 같은 시각에 맞춘 오디오 트랙을 처리합니다. 최종 믹스는 파생 파일로 생성하고 원본 트랙은 유지합니다.
- 원본 기준 SRT와 편집본 기준 SRT를 구분해 내보냅니다. 파일명과 결과 화면에 기준을 표시합니다.
- 렌더는 임시 결과에 기록하고 성공 검증 뒤 완성 파일로 전환합니다. 취소·디스크 부족·프로세스 중단이 원본이나 마지막 성공 결과를 훼손하지 않게 합니다.

### 다음으로 미룰 기능

클립 순서 변경·복제, 여러 영상의 자유로운 배치, 배속·역재생, 전환 효과, 자막 그래픽 애니메이션, 색보정, 플러그인 체계, 모든 NLE 프로젝트 형식 왕복 편집은 첫 확장에서 제외합니다. 외부 마이크 파일의 자동 싱크와 장시간 드리프트 보정도 별도 작업입니다.

‘트랙 합치기’는 여러 녹음 트랙을 하나의 소리로 믹스하는 기능입니다. 이미 한 트랙에 섞인 여러 사람의 목소리를 분리하는 기능과는 구현·평가 범위가 다릅니다. 화자별 마이크가 있으면 분석 시 그 구분을 유지하고, 배포용 믹스는 뒤에서 만듭니다.

### 오디오 믹스 계약

초기 믹서의 입력별 설정은 `trackId`, `enabled`, `gainDb`, `mute`로 제한합니다. 미리듣기의 solo 상태는 별도 UI 상태로 두고, 내보내기에 적용하려면 사용자가 명시적으로 선택합니다. 볼륨 범위는 예를 들어 -60~+12 dB로 제한하며 mute를 별도 값으로 저장합니다.

분석 대상 트랙과 청취용 믹스 설정도 분리합니다. 청취용 볼륨을 바꾸었다고 기존 전사문을 조용히 교체하지 않습니다. 입력 트랙이 짧으면 소스 영상의 끝까지 무음으로 채우고, 길면 소스 길이에 맞춰 처리하는 정책을 UI와 결과에 표시합니다. 전부 mute여도 무음 결과라는 표시 아래 처리할 수 있어야 합니다.

내보내기 전 피크·클리핑 여부를 확인하고, 보호용 리미터 적용 여부를 결과 설정에 기록합니다. 합칠수록 소리가 작아지거나 특정 트랙 종료 시 크기가 변하는 일이 없도록 믹스 정규화 정책을 고정합니다. FFmpeg의 `volume`, `amix`, `alimiter` 등으로 구현할 수 있지만, 채널·길이·정규화 기본값을 명시해야 합니다. [FFmpeg 필터 문서](https://ffmpeg.org/ffmpeg-filters.html#amix)

## 원본 시간 → 출력 시간 데이터 계약 제안

### 저장 원칙

자막과 메모의 권위 있는 좌표는 계속 **원본 시간**입니다. 삭제 구간에 맞춰 기존 `Caption.start/end`, `Note.start/end`를 반복해서 당기지 않습니다. 출력 위치는 편집 결정을 읽어 계산한 파생 값으로 만듭니다.

v0.1 JSON의 초 단위 필드는 그대로 읽습니다. 새 데이터가 필요해질 때 `schemaVersion: 2` 마이그레이션을 추가하고, v1 원본을 자동 덮어쓰지 않습니다. 새 편집 결정과 계산에는 안전한 정수 범위의 마이크로초를 사용하고, v1 시간은 최초 변환에서 한 번만 반올림합니다. 프레임레이트는 `30000/1001`처럼 분수로 보관합니다.

아래는 **제안 타입**입니다. 실제 `src/domain.ts`에 이미 존재하는 API가 아닙니다.

```ts
type TimeUs = number; // 유한한 0 이상 safe integer. 단위: microseconds.

type SourceRef = {
  id: string;
  displayName: string;
  durationUs: TimeUs;
  contentHash: string; // 재연결 시 다른 파일을 같은 원본으로 취급하지 않도록 비교
  frameRate: { numerator: number; denominator: number } | null;
};

type DeleteRange = { id: string; startUs: TimeUs; endUs: TimeUs };

type EditDecision = {
  id: string;
  revision: number;
  sourceId: string;
  sourceHash: string;
  deleteRanges: DeleteRange[];
  tracks: Array<{ trackId: string; enabled: boolean; gainDb: number; mute: boolean }>;
};

type KeepSpan = { // EditDecision에서 계산. 별도로 직접 수정하지 않음.
  sourceStartUs: TimeUs;
  sourceEndUs: TimeUs;
  outputStartUs: TimeUs;
  outputEndUs: TimeUs;
};

type MappedFragment = {
  sourceItemId: string; // 원본 caption 또는 note ID
  fragmentIndex: number;
  sourceStartUs: TimeUs;
  sourceEndUs: TimeUs;
  outputStartUs: TimeUs;
  outputEndUs: TimeUs;
  reviewReason: 'cut_boundary' | 'word_clipped' | null;
};
```

`deleteRanges`는 `[start, end)` 반열린 구간이고 소스 범위 안에 있어야 합니다. 겹치거나 인접한 삭제 구간은 정규화하여 중복 차감하지 않습니다. 삭제의 여집합을 원본 순서대로 유지 구간으로 만든 후, 앞선 유지 구간 길이의 합을 `outputStartUs`로 정합니다.

유지 구간 안의 원본 시각 `s`는 `outputStartUs + (s - sourceStartUs)`로 옮깁니다. 삭제된 지점에는 출력 시각이 없으므로 `null`을 반환합니다. 이전 프레임이나 다음 문장으로 임의 이동하지 않습니다. 반대 방향 탐색도 유지 구간 표를 사용하며, 컷이 맞닿은 출력 경계는 오른쪽 구간의 시작으로 정의합니다.

마지막 렌더에는 `sourceHash`, 편집 revision, 실제 사용한 유지 구간, 출력 길이·FPS·오디오 sample rate를 함께 기록합니다. 프레임·샘플 경계에 맞추는 과정에서 발생한 유효 구간을 영상과 자막 출력에 동일하게 적용해야 합니다. 첫 버전에서 속도 변경을 제외하면 시간 매핑을 이 선형 구간 계산으로 제한할 수 있습니다.

### 구체적 예시

원본 92초에서 `[10,20)`, `[50,55)`를 삭제하면 결과는 77초입니다.

| 원본 유지 구간 | 출력 구간 | 매핑 |
| --- | --- | --- |
| 0~10초 | 0~10초 | 동일 |
| 20~50초 | 10~40초 | 10초 차감 |
| 55~92초 | 40~77초 | 15초 차감 |

- 원본 30초의 자막은 출력 20초로 갑니다.
- 원본 52초의 점 메모는 `cut_away` 상태이며 출력 시각은 없습니다. 원본 메모는 유지합니다.
- 원본 48~58초의 범위 메모는 출력 38~40초와 40~43초의 두 조각에 연결됩니다. 내용·완료 상태는 하나의 원본 note ID를 계속 참조합니다.
- 원본 8~24초의 자막은 두 유지 구간에 걸칩니다. 출력 위치는 8~10초와 10~14초지만, 대사 전체를 두 조각에 그대로 복사하면 삭제한 발화까지 남습니다. 아래 정책으로 처리해야 합니다.

### 컷 경계를 넘는 자막과 메모

| 원본 항목 상태 | 편집본 처리 | 데이터 보존 |
| --- | --- | --- |
| 유지 구간 안의 자막 | 시간만 매핑 | 원본 텍스트·화자 유지 |
| 완전히 삭제된 자막 | 편집본 SRT에는 제외 | 원본 보기·JSON에는 유지 |
| 단어 시간이 있고 컷을 넘는 자막 | 살아남은 단어로 조각 구성; 단어 중간을 자르면 검수 표시 | 원본 caption ID와 단어 근거 유지 |
| 단어 시간이 없거나 수정으로 무효화된 자막 | 자동으로 대사를 추측해 자르지 않음; 조각별 내용 검수 필요 | 검수 전 편집본 SRT 확정 출력 제한, 원본 SRT는 가능 |
| 삭제 구간 안의 점 메모 | 편집본에는 `cut_away` 표시 | 원본 시각과 내용을 별도 목록에 남김 |
| 여러 유지 구간을 가로지르는 메모 | 한 note의 여러 출력 앵커로 표시 | 별도 note를 복제해 상태를 갈라놓지 않음 |

자막이 애매한 컷 경계에서 사용자가 문구를 확정하면 원본 자막을 수정하는 대신, `sourceCaptionId + editRevision + fragmentIndex`에 연결된 편집본 수정값을 저장합니다. 컷이 다시 바뀌면 이 수정값을 자동 재사용하지 말고 유효성을 확인합니다. 초기 UI에서는 원본 자막 편집과 편집본 조각 검수를 구분하고, 드래그로 컷을 가로질러 자막을 이동하는 기능은 제한합니다.

영상·음성의 구간 절단과 이어 붙이기에는 FFmpeg `trim`/`atrim`, 타임스탬프 재설정, 연결 필터를 사용하는 경로를 검토합니다. 정확한 경계 편집은 재인코딩 경로로 검증하고, 첫 구현에서 빠른 무재인코딩 출력을 동일 정확도로 약속하지 않습니다. [FFmpeg 필터 문서](https://ffmpeg.org/ffmpeg-filters.html#trim)

### v0.2 수용 테스트

1. 삭제 0개·첫/끝 구간·겹친 삭제·전체 삭제에서 길이와 매핑이 맞습니다. 전체가 삭제되면 빈 결과를 명시하고 렌더를 실행하지 않습니다.
2. 단어 중간·자막 중간·겹친 화자·메모 중간을 잘라도 원본 데이터가 보존되고 검수 대상이 사라지지 않습니다.
3. 동일 편집을 저장·재열기·실행 취소·다시 실행한 결과가 일치합니다. 다른 파일을 원본으로 연결하면 hash 불일치를 표시합니다.
4. 29.97fps와 가변 프레임레이트 원본에서 출력의 시작·중간·끝을 직접 재생해 음성/자막 오차를 측정합니다. 합성 프레임·비프 테스트와 실제 파일 확인을 구분합니다.
5. 트랙 gain·mute, 짧은 트랙, 모든 트랙 mute, 피크 초과, 렌더 취소와 디스크 부족을 검증합니다.

## v0.3: 같은 전사 데이터의 인터뷰·회의록 보기

### 인터뷰

먼저 기존 자막의 원문을 인물·발화 단위로 이어 보는 화면을 만듭니다. 원문 모드에서는 머뭇거림·반복·짧은 맞장구를 임의 제거하지 않습니다. 읽기 좋게 다듬은 문장이 필요하면 별도 파생 문서로 만들어 원문과 비교합니다.

화자 이름과 인터뷰어/응답자 역할은 사용자가 정합니다. 질문·답변·추가 질문·기타 발화 분류는 수정 가능한 태그로 제공하고, AI 분류는 제안 상태에서 시작합니다. 한 질문에 여러 응답자가 답하거나 답변이 중간에 끊겨도 연결할 수 있도록 질문과 답변을 단순 일대일 관계로 고정하지 않습니다.

모든 문단에는 원본 caption ID 목록과 시간 범위가 있어야 하며, 클릭하면 원본을 확인합니다. 화자 병합·분리와 전사 수정이 인터뷰 화면에도 반영되어야 합니다. 자동으로 이름을 추정하거나 불확실한 화자를 다른 사람에게 확정 배정하지 않습니다.

### 회의록

회의록은 **전사 내용을 근거로 생성한 검수 전 초안**으로 표시합니다. 요약·논의 사항·결정 사항·할 일을 구분하고, 할 일의 담당자·기한이 발언에 없으면 각각 **미정**으로 둡니다. ‘하면 좋겠다’와 ‘하기로 결정했다’를 같은 상태로 처리하지 않습니다.

```ts
type EvidenceRef = {
  captionId: string;
  sourceId: string;
  sourceStartUs: TimeUs;
  sourceEndUs: TimeUs;
  excerpt: string; // 해당 전사 snapshot 안에서 실제로 찾을 수 있는 근거
};

type MinutesItem = {
  id: string;
  kind: 'summary' | 'discussion' | 'decision' | 'action';
  text: string;
  owner: { speakerId: string | null; explicitName: string | null } | null;
  dueText: string | null; // 발화에 명시된 기한만. 없으면 UI에서 '미정'.
  evidence: EvidenceRef[];
  status: 'draft' | 'reviewed' | 'rejected' | 'stale';
};

type MinutesDraft = {
  sourceScope: 'full_source' | 'edited_version';
  transcriptRevision: string;
  editRevision: number | null;
  provider: 'local' | 'api';
  modelId: string;
  generatedAt: string;
  audioOutput: 'none';
  items: MinutesItem[];
};
```

근거 ID와 시간은 모델이 자유롭게 만드는 값으로 믿지 않고 현재 snapshot에서 조회해 검증합니다. 근거 문구가 없거나 다른 화자의 발언이면 확인 대상으로 남깁니다. 인용이 존재한다는 검사만으로 요약의 의미까지 검증되지는 않으므로, 결정·할 일은 원문을 함께 보여 주고 사람이 확정합니다. 상대적 기한 ‘다음 주’는 회의 날짜가 확인되지 않으면 임의 날짜로 변환하지 않습니다.

전사가 바뀌면 영향을 받은 회의록을 `stale`로 표시합니다. 새 분석 결과나 재생성 초안이 사용자가 확정·수정한 회의록을 덮어쓰지 않도록 revision을 보관하고 차이를 비교합니다. ‘전체 원본 회의록’과 ‘편집본에 남은 발언만의 회의록’ 중 범위를 명시적으로 선택하며, 기본은 전체 원본입니다. 컷 변경만으로 원본 회의록의 의미가 조용히 바뀌어서는 안 됩니다.

### 로컬 LLM과 선택적 API

1. LLM 없이도 원문 인터뷰 보기·수동 질문/답변 태그·수동 회의록은 사용할 수 있게 합니다.
2. 자동 초안은 로컬 LLM과 선택적 외부 API 중 사용자가 선택합니다. 설치된 모델·메모리·한국어 품질을 확인한 뒤 연결하며, 특정 모델의 품질을 미리 보장하지 않습니다.
3. 외부 API를 선택하면 전송할 검수된 전사 텍스트와 범위, 비용 발생 여부를 먼저 표시합니다. 자동으로 다른 공급자에게 재전송하거나 원본 음성을 보내는 fallback은 만들지 않습니다.
4. 이 기능은 텍스트 문서 생성입니다. `audioOutput: 'none'`을 유지하며 TTS, 가상 마이크 출력, 다른 앱으로의 소리 송출은 포함하지 않습니다.

### v0.3 수용 테스트

- 담당자·기한·합의가 없는 대화에서 이를 창작하지 않고 미정 또는 논의 중으로 표시합니다.
- 부정·번복·유보·농담·서로 다른 제안이 결정 사항으로 잘못 합쳐지는 사례를 포함해 검수합니다.
- 모든 생성 항목의 caption ID·근거 문구·원본 시간 링크가 유효합니다. 전사 삭제·수정 후 오래된 근거가 그대로 확정 상태로 남지 않습니다.
- 한국어 고유명사·겹친 발화·미배정 화자를 포함한 실제 자료에서 수정 시간을 측정합니다. 형식 검증 통과와 요약 의미의 정확도는 별도 결과로 기록합니다.
- 로컬 모델 중단·API 실패·취소·재생성에서도 기존 전사와 사람이 확정한 회의록을 보존합니다.

## 다음 구현을 시작할 때 고정할 결정

v0.2는 **원본 한 개의 구간 삭제 + 동기화된 최대 4트랙 믹스 + 출력 시간에 맞춘 자막**으로 범위를 고정하는 것이 좋습니다. v0.3은 원문 인터뷰 보기를 먼저 완성하고 회의록 자동 초안을 뒤에 붙입니다. 라이브 기록은 별도 계획의 장치·기록 검증을 통과한 후, 파일 입력과 같은 caption·note·source revision 구조로 연결합니다.

각 버전은 문서 제안, 코드 구현, 자동 검사, 실제 파일/장치 검증, 사용자 편집 시간 개선을 구분해서 기록합니다. 이 문서의 단계와 개발량은 해당 구현을 진행하기 전에 검토할 제안입니다.
